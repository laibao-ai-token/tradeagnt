## 二、现状分析

### 2.1 data-service (核心服务)

**职责**：
- WebSocket K线实时采集 (Binance Futures)
- 期货指标采集 (5m粒度，5个API)
- 历史数据补齐 (ZIP + REST)
- 缺口自动检测与修复

**依赖**：
- TimescaleDB (写入)
- Binance WebSocket/REST API
- Gate.io API (备用)

**关键文件**：
```
data-service/
├── src/collectors/
│   ├── ws.py          # WebSocket K线采集
│   ├── metrics.py     # 期货指标采集
│   ├── backfill.py    # 历史数据补齐
│   ├── alpha.py       # Alpha 代币列表采集 [审计补充]
│   └── downloader.py  # 通用下载器 [审计补充]
└── src/adapters/
    ├── timescale.py   # TimescaleDB 适配
    ├── cryptofeed.py  # Binance WS 适配
    ├── ccxt.py        # REST API 适配
    ├── gate_spot.py   # Gate.io 备用数据源 [审计补充-重要]
    ├── rate_limiter.py # 全局限流器 [审计补充]
    └── metrics.py     # 监控指标 [审计补充]
```

> **审计发现**：文档遗漏了 `gate_spot.py`（Gate.io 备用数据源），这是 Binance 不可达时的关键 fallback 机制。

### 2.3 tui-service 基金数据问题（需重构）

**当前问题**：
- 基金数据直接在 tui-service 中获取，未持久化
- 数据流向：`tui-service → 腾讯/天天基金 API → 展示`（无历史数据）

**问题分析**：
1. tui-service 承担了数据获取职责，违反单一职责原则
2. 数据不持久化，无法做历史分析和回测
3. tui 关闭后没有基金数据

**基金数据来源**：

| 类型 | 数据源 | 示例 |
|:---|:---|:---|

| 场外基金 | 天天基金估值 | `024389` (6位代码) |

**重构目标**：
```
重构前: tui-service ──直接调用──► 腾讯/天天基金 API（无持久化）
重构后: collector-service ──采集──► TimescaleDB ──读取──► tui-service
```

## 五、风险评估

### 5.1 审计发现的问题

| 问题 | 风险等级 | 说明 |
|:---|:---:|:---|
| 文档遗漏 `gate_spot.py` 备用源 | **高** | Binance 不可达时的 fallback 能力丢失 |
| 文档遗漏 `schema_adapter.py` | **高** | raw/legacy 双模式兼容方案不完整 |
| 文档遗漏 `storage/` 存储层 | **中** | 可能重复实现存储逻辑 |
| 文档遗漏 `core/` 基础设施 | **中** | Provider 注册机制未考虑 |
| SQL 注入隐患 | **中** | data-service 使用 f-string 构建 SQL |
| 配置命名不统一 | **中** | 环境变量差异大，需统一重命名 |

### 5.2 原有风险评估

| 风险 | 影响 | 缓解措施 |
|:---|:---|:---|
| 采集中断 | 数据缺失 | 灰度切换，并行运行一段时间 |
| 配置冲突 | 启动失败 | 统一配置格式，向后兼容 |
| 依赖冲突 | 运行时错误 | 虚拟环境隔离，依赖锁定 |

**总体风险等级**: 中等偏高

### 7.3 基金数据重构要点

**原架构问题**：
```
tui-service ──直接调用──► 腾讯/天天基金 API ──► 展示
                          （无持久化，无历史数据）
```

**新架构设计**：
```
collector-service                    tui-service
      │                                   │
      ├── 场内ETF采集 ◄── 腾讯行情 API ──┤
      │         │                        │
      │         ▼                        │
      │   TimescaleDB ◄─────────────────►│ 只读展示
      │         ▲                        │
      │         │                        │
      └── 场外基金采集 ◄── 天天基金 API ──┘
```

**数据库表设计**：
```sql
-- 场内基金 (ETF/LOF)
CREATE TABLE market_data.fund_cn_etf (
    symbol TEXT NOT NULL,           -- SH510300, SZ159915
    timestamp TIMESTAMPTZ NOT NULL,
    open REAL,
    high REAL,
    low REAL,
    close REAL,
    volume REAL,
    amount REAL,
    PRIMARY KEY (symbol, timestamp)
);

-- 场外基金估值
CREATE TABLE market_data.fund_cn_offmarket (
    fund_code TEXT NOT NULL,        -- 6位代码: 024389
    timestamp TIMESTAMPTZ NOT NULL,
    estimated_nav REAL,             -- 估值净值
    estimated_change_pct REAL,      -- 估值涨跌幅
    PRIMARY KEY (fund_code, timestamp)
);
```
