# tradeagnt 控制面（你与主 Agent 的唯一协作入口）

> **你只必读这一页 + 当前迭代的 `EXEC_SUMMARY.md`。**  
> 其余 PRD/AC/里程碑由主 Agent 维护；子 Agent 只执行、不直接对你说话。

---

## 1. 问题与原则

| 问题 | 原则 |
|:---|:---|
| 你的上下文短、Agent 上下文长 | **对外只产出「一层摘要」**；细节进子目录，默认不推给你读 |
| 需求被拆成很多文件/提交 | **一个「当前任务包」**；完成前不并行开新主题 |
| 你无法掌控每个细节 | **你先批「范围」，主 Agent 再拆给子 Agent**；你只验收摘要里的 Done/Next/Risk |

---

## 2. 角色（单入口 + 子执行）

```text
你（产品/决策）
    ↕  只对齐、拍板（短）
主 Agent（CEO / 编排）
    → 拆任务、写/改 PRD 条目、指定 AC
    → 派生子 Agent（检索 / 实现 / 测试）— 你不直接对话
    ← 汇总：一页 EXEC_SUMMARY + 3～7 条结论
子 Agent
    → 按任务单执行，回报给主 Agent（不向你刷屏）
```

**默认**：本仓库会话里，**你是和「主 Agent」一个人说话**；需要并行时用 Cursor Task，但**只有主 Agent 向你汇报**。

## 4. 主 Agent ↔ 你的每一轮对话（强制）

**范围**：不仅「派子 Agent 之后」——**你我之间的每次回复**都遵守本节，包括答疑、排障、写码、改 PRD。  
子 Agent 不直接对你说话；**我就是你唯一的对外接口**。

每次回复主 Agent **必须**用下面模板（控制在屏幕 1～2 屏内）；若本轮仅闲聊/确认、无进展，可只保留「目标 + 下一步」两段：

```markdown
## 执行摘要（给决策者）
- **目标**：（一句话）
- **已完成**：（最多 5 条，带分支/路径）
- **未完成 / 等你拍板**：（最多 3 条，含建议默认）
- **风险**：（0～2 条，没有写「无」）
- **细节在哪**：（只列 1～3 个路径，不贴长文）

## 下一步（需你回复时写）
- [ ] 选项 A / B（默认 A）
```

**禁止**：一次性贴 3 个以上新 MD 全文；禁止未摘要的 `git diff` 墙。

---

## 5. 子 Agent 任务单（主 Agent 内部用）

主 Agent 派活时附带：

1. **任务 ID**（如 `V2-M1-schema`）
2. **只读/可写路径**（避免改同一文件）
3. **退出条件**（对应 `AC-xx` 或「交付路径列表」）
4. **回报格式**：≤15 行 bullet + 改动文件列表

子 Agent 完成后，主 Agent 合并进 `EXEC_SUMMARY.md` 的「已完成」。
